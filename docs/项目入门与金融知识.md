# 项目入门与金融知识

核对日期：2026 年 9 月 23 日。依据：当前代码、现有验证报告和文中引用的官方资料。

**先说结论：项目已经能完成模拟交易、历史回测和基础自动交易流程；目前适合学习与策略研究，尚缺少无人值守实盘所需的保护和恢复能力，也没有稳定盈利的证据。**

本文中的金额统一以泰达币计价，数字例子只用于解释计算方式。

## 1. 这个项目到底做什么

可以把它理解成一个“按固定规则工作的交易助手”：你设定交易品种、资金和止损条件，程序持续读取行情，出现指定信号就尝试开仓，达到退出条件就尝试平仓。

当前只有一套趋势跟随策略，可同时监测 1～8 个币种；这些币种共用一套参数。每个币种最多保留一个方向的仓位，同向信号不会继续加仓。

| 你在页面上看到的功能 | 实际用途 |
| --- | --- |
| 总览 | 查看行情、持仓、盈亏、运行状态和风险额度 |
| 策略配置 | 设置币种、周期、杠杆、资金、指标和止盈止损 |
| 历史回测 | 把规则放到过去的行情中演练，不下真实订单 |
| 成交记录 | 查看最近记录、按条件筛选并导出 |
| 系统设置 | 查看密钥配置状态、访问保护状态、重置模拟账户 |

### 四种使用环境

| 环境 | 价格从哪里来 | 钱和订单在哪里 |
| --- | --- | --- |
| 演示行情模拟盘 | 程序生成 | 本地虚拟记账 |
| 真实行情模拟盘 | 币安公开行情 | 本地虚拟记账 |
| 测试网 | 币安测试环境 | 交易所测试资产与测试订单 |
| 实盘 | 币安真实环境 | 交易所真实资金与真实订单 |

默认是第一种，策略停止、没有仓位。真实行情模拟盘无需交易密钥，但需要能连接币安公开行情。四种环境的本地账本分别保存；这不是可以同时管理多个真实账户的系统。

## 2. 当前还缺少什么

### 已经做到的

- 参数检查、行情有效性检查，只使用已收盘行情判断开仓信号。
- 金叉开多、死叉开空；反向信号先平仓，确认成功后才考虑反向开仓。
- 止盈止损、单笔及总保证金限制、每日亏损锁定。
- 记录订单意图、确认成交后记账；结果不明时阻止盲目重发。
- 数据持久化、环境账本隔离、控制台口令、同源和访问域名检查。
- 交易所接入代码，包括权限、余额、仓位、下单数量规则等校验。

### 需要补齐的，按实盘重要程度排序

| 优先级 | 缺口 | 为什么影响使用 |
| --- | --- | --- |
| 实盘前优先 | 交易所托管止损等保护单 | 现在靠后台轮询止损；断网、休眠、服务退出时，本地程序无法继续保护仓位 |
| 实盘前优先 | 测试网账户完整联调 | 有接入代码和模拟响应测试，还没有真实测试账户开仓、平仓、费用与故障恢复的验证证据 |
| 实盘前优先 | 未知订单、部分成交、仓位不一致的核对与恢复流程 | 现在会停下来防止重复下单，但没有核对后恢复的操作界面；部分明确拒单也可能被保守地锁住 |
| 实盘前优先 | 准确的交易所价格与账单口径 | 当前浮盈和本地止损使用最新成交价；资金费、充提资金没有独立归因，不能当作完整交易所账单 |
| 长期运行前 | 异常通知、备份恢复演练、持续在线部署验证 | 页面有日志，但缺少主动通知；已有容器配置不等于已经验证全天稳定运行 |
| 判断策略价值前 | 更长历史、不同市场阶段、独立样本和持续模拟 | 最近最多一千根行情不足以判断长期表现；还应加入资金费、强平和更真实的成交成本 |
| 使用体验 | 自选回测日期、完整历史查询导出、回测报告留档 | 当前只回测单币种最近样本，页面只查询并导出最近最多 200 条订单记录 |

现有报告中，9 月 22 日保存的三个真实行情回测样本都亏损。这只说明那个时间窗口的默认参数表现，不能推断未来。参见[已有验证报告](validation/2026-09-22-review.md)。

**先补保护、核对和验证，再考虑增加策略。** 多账户、多策略和高频交易属于后续扩展，当前个人学习版不必先做。

## 3. 整个流程怎么走

> 保存参数 → 启动检查 → 获取行情 → 先检查已有仓位风险 → 判断新的收盘信号 → 检查资金 → 执行订单 → 确认成交 → 保存账本 → 页面刷新

| 步骤 | 程序具体做什么 |
| --- | --- |
| ① 保存参数 | 前端先检查，后端再检查。运行中、有持仓或有未知订单时，不能随意修改配置 |
| ② 点击启动 | 检查每日亏损、行情和指标数据；测试网及实盘还要检查账户权限、单向持仓、单资产保证金、余额、外部仓位和挂单 |
| ③ 建立起点 | 记住当前最新的已收盘行情，等待下一次新交叉；不会一启动就补做旧信号 |
| ④ 后台巡检 | 每轮处理完后等待 5 秒，再进入下一轮；网络请求也耗时，所以不是严格每 5 秒完成一次 |
| ⑤ 优先处理风险 | 更新持仓浮盈，检查每日亏损、保证金、止盈止损；退出条件不必等下一根行情收盘 |
| ⑥ 判断新信号 | 新的一根行情收盘后计算指标；金叉倾向开多，死叉倾向开空，无交叉就等待 |
| ⑦ 检查是否能开仓 | 同向已有仓位就不加仓；反向已有仓位先平掉，再根据“允许反手”和资金限制决定是否开新仓 |
| ⑧ 执行并记账 | 模拟盘按价格和成本本地计算；测试网、实盘发送市价单，确认成交后保存仓位、费用和订单 |
| ⑨ 更新页面 | 状态大约每 5 秒刷新一次，行情图大约每 15 秒刷新一次；网页刷新频率和交易执行频率是两回事 |

下单前先留下带唯一编号的“订单意图”，就像先记一张待确认收据。下单超时后查询原订单，不能直接再买一次，因为第一次可能已经成交。这个处理原则也符合[币安接口总则](https://developers.binance.com/en/docs/products/derivatives-trading-usds-futures/general-info)。

### 几个按钮的区别

| 操作 | 实际效果 |
| --- | --- |
| 保存配置 | 只保存，不自动启动 |
| 停止策略 | 禁止新开仓，后台继续尝试管理已有仓位风险 |
| 全部平仓 | 先停止策略，再尝试平掉本程序记录的仓位；失败时要核对结果 |
| 关闭网页 | 后台进程仍运行时，策略继续工作 |
| 退出后台或电脑休眠 | 本地监测和止损无法继续正常执行 |
| 重启后台 | 恢复保存的账本，不自动恢复新开仓；持仓核对通过且连接可用时继续尝试风险管理 |

真实环境停止后若还有仓位，重新启动会要求先核对并平仓。当天亏损锁定不能靠行情反弹或重启解除，跨日解除后还需要手动启动。

## 4. 技术架构和选型，用人话解释

这是一个**前后端分工、单进程部署的模块化应用**。网页负责按钮和图表，后端负责决策和下单，数据库负责记账。

> 浏览器操作台 ⇄ 后端接口 ⇄ 交易引擎 ⇄ 行情与交易所
>
> 交易引擎 ⇄ 本地数据库；历史回测走独立的计算流程

以下“适合的原因”是根据当前实现和个人工具规模作出的判断。

| 部分 | 当前技术 | 在这里做什么、为什么适合 |
| --- | --- | --- |
| 网页界面 | React 19<br>中文：用于搭建网页组件的库 | 把页面、表单和表格拆成可维护的小块 |
| 前端类型 | TypeScript 7<br>中文：带类型检查的脚本语言 | 提前检查前后端字段和组件参数是否用错 |
| 网页构建 | Vite 8<br>中文：前端开发与打包工具 | 开发时自动刷新，交付时打包成静态网页 |
| 后端语言 | Python<br>中文：适合数据计算和服务开发的编程语言 | 编写指标、回测、交易和风险规则 |
| 后端接口 | FastAPI + Uvicorn<br>中文：接口框架和服务运行器 | 接收网页请求、返回状态，同时运行后台任务 |
| 参数模型 | Pydantic 2<br>中文：数据结构与校验库 | 检查类型、金额范围以及“快线周期必须小于慢线”等关系 |
| 交易所通信 | HTTPX<br>中文：支持异步请求的网络客户端库 | 拉行情和账户信息、发送交易请求 |
| 数据保存 | SQLite<br>中文：以文件保存的轻量关系数据库 | 不用额外安装数据库服务，适合单机个人工具 |
| 图表 | SVG<br>中文：可缩放矢量图形 | 直接在网页绘制行情、指标和资金曲线 |
| 部署 | Docker Compose<br>中文：容器构建和启动配置工具 | 把网页与后端装进同一个运行环境，并挂载持久数据卷 |

正式使用时，后端同时提供网页和接口，只需打开一个地址。开发时，网页开发服务与后端分开启动，网页请求会转发给后端。

| 模块入口 | 通俗职责 |

| [交易所模块](../backend/exchange.py) | 处理账户检查、数量精度、市价下单和平仓 |
| [网络模块](../backend/binance_http.py) | 为交易请求加时间戳和签名，处理通信错误 |
| [存储模块](../backend/storage.py) | 保存配置、账户、订单意图、成交和日志 |

数据在概念上只有几类：**策略配置、行情、运行状态、持仓、订单、日志**。底层使用数据库表保存，复杂状态以结构化文本存储；成交记录与账户变更放在同一次数据库事务里提交，减少“有成交、没记账”的情况。

程序内的资金操作排队执行；进程之间通过文件锁保护同一个数据库。但它不能阻止你用另一个数据库启动第二套程序，也不能阻止在交易所手动交易。因此，同一真实账户仍应只由一个实例管理。

## 5. 默认参数，应该怎样理解

| 参数 | 默认值 | 人话解释 |
| --- | --- | --- |
| 币种 | 比特币、以太坊 | 同时观察这两个合约 |
| 周期 | 15 分钟 | 每根蜡烛汇总 15 分钟的价格变化 |
| 指标周期 | 12 / 26 / 9 | 短期均线、长期均线、信号平滑的根数 |
| 模拟初始资金 | 10,000 | 虚拟账户起始余额；不会给真实账户充值 |
| 单笔保证金 | 100 | 每次开仓计划占用的担保资金 |
| 杠杆 | 3 倍 | 单笔计划控制约 300 的名义仓位；程序允许 1～20 倍，交易所仍有自己的限制 |
| 总保证金上限 | 1,000 | 本程序所有仓位占用保证金的合计限制，不是最大亏损保证 |
| 保证金模式 | 逐仓 | 真实交易向交易所申请该模式；模拟没有完整复现其强平机制 |
| 止损 / 止盈 | 2% / 4% | 按入场价格的变化幅度，不是按保证金收益率 |
| 每日亏损额度 | 200 | 当日权益损失达到该金额后，禁止开仓并尝试退出 |
| 单边手续费 / 滑点 | 4 / 2 基点 | 模拟参数分别相当于 0.04% / 0.02%，不是你的真实账户费率承诺 |
| 反向开仓 | 开启 | 反向信号先平旧仓，条件允许才开新方向 |

“策略资金”也不是交易所里的隔离子账户。实盘钱包余额来自交易所，实际下单规模主要由单笔保证金、杠杆和总保证金限制共同控制。

## 6. 金融知识汇总

### 6.1 现货、永续合约、泰达币

- **现货**：买入资产本身。
- **永续合约**：交易跟随标的价格变化的合约，没有固定到期日；可以做多，也可以做空。当前项目做的是泰达币计价、担保和结算的线性永续合约。
- **泰达币**：一种以美元价值为锚的稳定币，用作本项目金额单位；“稳定币”不等于没有价格或发行方风险。

USDT

中文：泰达币的交易代码。比如“比特币／泰达币”合约，就是用泰达币计算比特币合约的价格和盈亏。

### 6.2 做多、做空、开仓、平仓

| 概念 | 通俗解释 | 忽略成本的例子 |
| --- | --- | --- |
| 做多 | 希望价格上涨 | 100 入场、105 离场，每单位赚 5 |
| 做空 | 希望价格下跌 | 100 入场、95 离场，每单位赚 5 |
| 开仓 | 建立一笔交易敞口 | 开始承受价格变化带来的盈亏 |
| 平仓 | 结束已有仓位 | 将这笔浮动盈亏结算下来 |
| 反手 | 平掉旧方向后，再开相反方向 | 平多后开空，会产生新的交易成本 |

本项目只支持**单向持仓**：同一合约不能同时持有多仓和空仓。多个币种可以分别有不同方向。

### 6.3 保证金、杠杆、名义金额

**保证金像押金，名义金额是实际承受价格波动的仓位大小。** 合约杠杆可以这样理解，但并不是程序真的替你借来并买入同等数量的现货。

> 名义金额 ≈ 保证金 × 杠杆
>
> 持仓数量 ≈ 名义金额 ÷ 成交价格
>
> 多仓毛盈亏 =（平仓价 − 开仓价）× 数量
>
> 空仓毛盈亏 =（开仓价 − 平仓价）× 数量

例如：保证金 100、杠杆 3 倍，名义金额约 300；假设价格 100，持仓数量约 3。价格上涨到 102 时，多仓毛利润是 6，对这笔保证金的收益率是 6%；如果账户一共 10,000，这笔利润对整个账户的贡献只有 0.06%。以上都未扣成本。

数量已经包含杠杆效果，计算价格差盈亏后**不能再乘一次杠杆**。真实订单还要按交易所允许的数量步长向下取整，因此名义金额可能略小于计划。

### 6.4 逐仓、全仓、强制平仓

| 概念 | 人话解释 |
| --- | --- |
| 逐仓 | 给特定仓位分配保证金，风险主要围绕该仓位的保证金管理 |
| 全仓 | 多个仓位共用可用保证金，某个仓位亏损可能消耗更多账户资金 |
| 初始保证金 | 建立仓位需要的担保资金 |
| 维持保证金 | 保持仓位所需的最低保证金要求，会受仓位档位等规则影响 |
| 强平 | 保证金不足时，交易所强制减仓或平仓；俗称爆仓 |

杠杆越高，相同保证金对应的仓位越大，承受同样价格波动时越容易接近强平。不能用“价格反向走 1÷杠杆就一定爆仓”作为准确公式，还要考虑维持保证金、费用、仓位档位和保证金模式。

**本项目模拟盘和回测没有完整模拟强平，也没有分别复现逐仓与全仓的风险机制。** 因此，模拟里还能持有的仓位，实盘可能已经被强平。

### 6.5 最新成交价、指数价格、标记价格

- **最新成交价**：市场最近一笔成交的价格。
- **指数价格**：综合现货市场价格形成的参考值。
- **标记价格**：交易所用于风险计算的参考价格，币安合约强平按标记价格判断，不一定等于最近成交价。参见[币安强平说明](https://www.binance.com/en-NG/support/faq/detail/360033525271)。

**当前项目用最新成交价计算本地浮盈和止盈止损。** 虽然内部有名为“标记价格”的字段，它装的仍是最新成交价，尚未接入交易所真正的标记价格；控制台权益不能直接当成交易所强平依据。

### 6.6 蜡烛、均线和交叉信号

一根蜡烛记录一个时间段的**开盘价、最高价、最低价、收盘价和成交量**。15 分钟周期的“12 根”，是 12 个十五分钟，而不是 12 天。图中正在形成的蜡烛可以展示，但不会用于开仓信号。

切换图表周期只改变查看方式，不会更改已保存策略的交易周期。当前图中“区间涨跌”实际使用最近 24 小时涨跌数据，也不是所选图表区间的涨跌。

EMA

中文：指数移动平均线。可以把它理解成“更重视近期价格的平滑平均价”。本项目先用简单平均值预热，再逐根更新。

MACD

中文：指数平滑异同移动平均线。通过比较短期与长期平均价格，观察趋势和动量的变化。

本项目默认计算方式：

> 差值线 = 12 根指数均线 − 26 根指数均线
>
> 信号线 = 差值线的 9 根指数均线
>
> 柱值 = 差值线 − 信号线

柱值从不大于零变成大于零，即金叉，程序倾向开多；从不小于零变成小于零，即死叉，倾向开空。这里比较的是**差值线与信号线的交叉**。本项目柱值没有乘 2，和部分看盘软件显示的柱高可能不同。

指标来自历史价格，因此有滞后；震荡时可能反复交叉，造成反复交易和成本。交叉是执行规则，不是未来涨跌的保证。参见[富达指标说明](https://www.fidelity.com/learning-center/trading-investing/technical-analysis/technical-indicator-guide/macd)。

### 6.7 止盈、止损与每日亏损限制

假设实际入场价 100，价格止损 2%、止盈 4%：多仓的止损价为 98、止盈价为 104；空仓的止损价为 102、止盈价为 96。

在 3 倍杠杆下，2% 的不利价格变化约对应保证金 6% 的毛损失，还要加成本。**止损是触发退出的条件，不能保证恰好在该价格成交，也不能保证亏损封顶。**

每日亏损按“当前权益 − 当日起点权益”判断，包括浮动盈亏。项目按协调世界时自然日换日，对应北京时间每天早上 8 点；跨日停机时只能沿用最近保存权益，无法还原精确换日时刻。真实账户充值、提现也会改变这个差额，尚未单独剔除。

### 6.8 手续费、滑点、资金费

| 成本 | 通俗解释 | 项目如何处理 |
| --- | --- | --- |
| 手续费 | 每次成交支付的交易费用 | 模拟按配置计费；真实交易尽量读取实际成交费用，读不到时标记为估算 |
| 滑点 | 实际成交价与参考价格之间的差异 | 模拟把买价调高、卖价调低；真实交易以成交结果为准 |
| 资金费 | 永续合约多空双方之间定期支付的费用，用于帮助合约价格贴近现货参考价格 | 模拟与回测未计入；真实账户钱包同步会反映其影响，但没有单独账单归因 |

1 基点 = 0.01%。默认单边手续费 4 基点，即 0.04%。名义金额 300 时，开仓手续费约 0.12，平仓再收一次；往返约 0.24，实际平仓金额变化时费用也会变化。滑点 2 基点对应每次约 0.02% 的不利价格调整。

模拟滑点已经包含在成交价和盈亏里，不要再扣一次。真实下单以交易所返回的成交价格为准，不额外套用模拟滑点。

资金费通常按结算时的仓位名义价值乘资金费率计算：正费率时多方付给空方，负费率时反过来。结算周期可能因合约和规则调整，不能固定认为总是每八小时一次。参见[币安资金费率说明](https://www.binance.com/en/support/faq/detail/360033525031)。

### 6.9 钱包余额、权益、盈亏、仓位占用

| 指标 | 本项目的口径 |
| --- | --- |
| 钱包余额 | 模拟按成交更新；真实环境同步交易所钱包余额 |
| 未实现盈亏／浮盈浮亏 | 还没有平仓，按本地最新价格估算的账面变化 |
| 账户权益 | 钱包余额 + 本地计算的未实现盈亏；真实环境可能与交易所风险口径不同 |
| 累计已实现盈亏 | 本策略已平仓毛盈亏减去已发生手续费；当前未平仓的开仓手续费也已计入 |
| 单笔平仓净盈亏 | 该仓位毛盈亏 − 开仓手续费 − 平仓手续费 |
| 占用保证金 | 各仓位开仓时初始保证金的合计，不等于仓位名义金额 |
| 可用余额 | 模拟显示钱包余额减占用保证金，未完整模拟交易所可用保证金算法；真实环境读取交易所数据 |

注意：当前未平仓交易已经支付开仓费，所以“累计已实现盈亏”可能不等于页面中已平仓行盈亏之和。资金费、充提资金、外部活动也不能从该统计中完整还原。

页面的“保证金使用百分比”是占用保证金除以自己设置的上限，不是交易所的保证金率，也不是距离强平还有多少空间。

### 6.10 收益率、胜率、盈亏比、回撤

| 概念 | 计算方式 | 例子或限制 |
| --- | --- | --- |
| 回测收益率 | （期末权益 ÷ 初始资金 − 1）× 100% | 10,000 变为 10,500，收益率 5%；这是账户收益率 |
| 胜率 | 净盈利的已平仓交易数 ÷ 已平仓总数 | 10 笔中 6 笔盈利为 60%；打平不算赢，无交易时程序显示 0 |
| 平均盈亏比 | 平均盈利金额 ÷ 平均亏损金额的绝对值 | 高胜率仍可能被少数大亏抵消；当前页面未单独计算这个指标 |
| 最大回撤 | 历史峰值到后续低点的最大跌幅 | 权益从峰值 12,000 跌到 9,000，回撤为 25% |

本项目最大回撤只使用每根蜡烛收盘时的权益，可能漏掉盘中的更深下跌。已完成交易数按平仓次数统计；成交记录还包含开仓，所以两者条数不同。

另外，止盈 4%、止损 2% 只是目标价格距离比为 2；受到反向信号、成本和跳空影响，实际平均盈亏比不一定是 2。

### 6.11 回测、未来信息、过拟合与分散风险

**回测是在历史行情上演练规则。** 本项目用上一根收盘信号、下一根开盘模拟成交，避免提前知道未来收盘价；真实运行则在发现收盘信号后的轮询中发送市价单，成交时点不会完全相同。

当前回测还有这些边界：

- 只取最近最多 1,000 根，剔除未收盘数据，通常可用 999 根；15 分钟周期约十天，还要扣除指标预热。
- 同一根同时碰到止盈和止损，保守按止损处理；跳空越过阈值时按开盘价格退出，最后仍有仓位则在样本末尾平仓。
- 计入配置的手续费和滑点，但没有资金费、强平、盘口深度、真实延迟和部分成交模拟。
- 单币种独立使用完整初始资金，不能把几个币的回测结果相加当成共享资金组合；真实多币种运行还会竞争同一保证金额度。
- 反复调参数直到这段历史赚钱，可能只是“背答案”，即过拟合。应保留未参与调参的历史区间，再观察真实行情模拟表现；这些验证能力还需要扩展。
- 多买几个高度同涨同跌的币，不一定实现分散风险；当前只有总保证金约束，没有按相关性分配仓位。

## 7. 新手怎么启动和验证

首次运行需要后端语言环境 3.11 及以上、前端运行环境 22 及以上。命令适用于当前苹果电脑或类似系统，从项目目录运行；原生微软桌面系统尚未适配当前文件锁实现。

### 首次安装并启动

~~~sh
python3 -m venv .venv
.venv/bin/pip install --index-url https://pypi.org/simple -r requirements.lock
npm --prefix frontend ci
npm --prefix frontend run build
.venv/bin/python -m backend
~~~

中文：依次创建隔离的后端环境、安装固定版本的后端依赖、安装前端依赖、生成网页、启动后台。第一次可直接使用默认演示模拟盘。

然后打开[本机工作台](http://127.0.0.1:8765)。之后日常启动只需：

~~~sh
.venv/bin/python -m backend
~~~

中文：启动已经安装好的后端服务，同时提供已构建的网页。终端需要保持运行。

### 检查项目是否正常

~~~sh
.venv/bin/python -m pytest backend/tests -q
npm --prefix frontend test
npm --prefix frontend run build
~~~

中文：依次检查后端行为、前端逻辑，以及网页能否正确构建。自动测试使用测试数据，不代表真实交易已经联调。

本次重新执行结果：**后端 114 项通过，前端 11 项通过，网页正式构建成功**。有 2 条后端依赖弃用告警和 2 条图标库打包告警，未阻断验证；本次没有执行交易所账户开仓或平仓验证。

建议的学习顺序是：**演示模拟熟悉按钮 → 真实行情模拟观察行为 → 历史回测理解数据 → 补齐实盘前缺口并完成测试网验证 → 再评估是否使用真实资金。**

密钥设置、开发服务和容器部署的详细命令见[项目说明](../README.md)。设置页显示“已配置”仅说明检测到相关配置，不代表已成功连接或可以正常成交。
